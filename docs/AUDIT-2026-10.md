# visual-editor — October 2026 audit

> Fresh audit of the repo as it stood after the May 2026 publish (v0.2.0/0.2.1 on npm,
> zero stars / issues / external users as of 2026-10-09), plus what was changed in
> response. Read `PROJECT_CONTEXT.md` first for the principles; this document is about
> where the shipped tool fell short of them and what v0.3 does about it.

## TL;DR

The core idea held up: deterministic AST edits from pointer gestures, loud refusals,
Claude as reviewer. What did **not** hold up was everything around it:

## What the research said

Searched the current (Oct 2026) landscape and the docs for Next 16.4 / Turbopack / instrumentation:

- **react-grab** (⌘C to copy element context) is the lightest competitor: a script tag, no build
  step, works with any agent — but it only knows the *component* location (React 19 dropped
  element-level `__source`), it can't edit, and it can't count instances. Our build-time stamp is
  what buys element-level precision and deterministic edits; the price was install friction, which
  v0.3 cuts to one config wrapper.
- **stagewise** pivoted to its own agentic IDE; **Onlook** runs your project in a sandbox. Neither is
  "overlay on your real dev server + your agent", which remains the gap.
- **feedback-studio** (Claude Code plugin) validated the *pins* pattern: drop annotated comments on
  the page, let the agent process the batch, track status. v0.3 adopts it, with the difference that
  our pins carry exact source refs and editability, so the agent often doesn't need to search.
- Turbopack docs: custom CommonJS loaders via `turbopack.rules`, `condition: { not: "foreign" }`
  (16.0+). Next 16.3 added `instrumentationClientInject` precisely for config-wrapper plugins to
  inject client code — the hook that makes the layout edit unnecessary.
- SWC wasm plugins were evaluated and rejected: `swc_core` ABI pinning per Next release would make
  every Next patch a potential break. A string-insertion loader (magic-string) sidesteps the
  problem entirely because the real compile still happens in SWC.
- Reddit was unreachable from the tooling (login wall); the sentiment data came from dev.to,
  GitHub READMEs and the Chrome Web Store listings of the half-dozen small "element picker →
  Claude Code" tools that appeared in 2026. The common thread in all of them: users want to
  **point**, add a **short note**, and have the agent **not guess the file**.

## The "how should the user share context with me" answer

From the agent's seat, the ideal input for a visual fix is: **exact location + what the user
sees + what they want**, with nothing to guess. v0.3 gives three ways to send that, from zero-setup
to fully wired:

1. **Copy context** (any agent, no MCP). One click copies a block like:
   ```
   [visual-editor] <button> in Button — components/ui/button.tsx:30:4
   used at: app/page.tsx:42:8 (in Page)
   className @ call site: p-4 bg-red-500
   className @ host: cn(… +1 dynamic) — not editable: className is cn(...) with 1 non-static argument(s)
   renders 3 instances · 96×36px · padding 16px · font-size 14px
   note: too loud, make it secondary
   ```
2. **Pins + `/visual-editor`** (Claude Code). Walk the page, pin elements with notes, then one
   command processes the batch. The agent gets refs with editability so it knows whether a token
   swap is provable or it has to edit by hand; it can `highlight_element` to ask "this one?" and
   `resolve_pin` so the user sees green checkmarks in the browser.
3. **Gestures** (no language at all). Drag/nudge → Apply writes the token. The agent is only
   involved to review the diff and commit.

## Verified in this audit (2026-10-09)

- Spike app (Next 16.4.0 / React 19.3 / Tailwind 4.3): no `babel.config.js`, overlay auto-mounted via
  `instrumentationClientInject`, stamps present in SSR HTML for host elements + styled call site +
  CSS Module hints, zero loader warnings, zero hydration errors from the tool, click → `]` → Apply
  wrote `p-4 → p-5` to the correct file, cross-site and `text/plain` writes refused, SSE highlight
  delivered to the open tab, pin created and listed.
- Test suites: server 138/138 (incl. 8 new stamper tests with a Babel-plugin parity check),
  MCP 10/10, all packages typecheck.
- Known, unrelated noise: a browser extension on the dev machine (`js-storylane-extension`) adds a
  class to `<html>` and triggers React's hydration warning; not caused by visual-editor.

## Still open (v0.3.x → v0.4)

- **Pages Router**: hover works, writes need a `pages/api` adapter (the core is transport-agnostic;
  ~40 lines).
- **Inline `style={{}}` objects** and **global CSS** (`.btn` in `globals.css`) — the two styling
  systems after Tailwind / CSS Modules / styled-components that the describer can't edit yet.
- **CVA variants** — `cva(base, { variants })`: the base string is mutable in principle; variants
  need a structured editor.
- **Screenshots in context** — the overlay can't screenshot itself; Claude Code can via its browser
  tools when needed.
- **Runtime overlay tests** — the 3.5k-line overlay has only Playwright smoke scripts, no unit tests.
- **Trusted Publishing / provenance** on npm is still pending (see `PUBLISHING.md`).
